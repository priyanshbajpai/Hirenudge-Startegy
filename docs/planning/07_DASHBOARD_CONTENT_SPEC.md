# 1. Overview

## Founder dashboard content

### Page title

`Protect trust. Prove one job-centered outcome. Expand only from evidence.`

### Strategic summary

`HireNudge has broad candidate-workflow coverage, but the supplied evidence does not prove a coherent, retained or outcome-improving product. The immediate strategy is to protect trust, define activation, connect one real application from role selection to outcome, and test that workflow with a narrow India-based cohort.`

### Strongest findings

1. Product breadth is visible; product-market fit is not.
2. The interface is module-first when the user's task is job-first.
3. Numeric scores carry more certainty than the supplied methodology supports.
4. Job freshness, source rights, expiry and duplicates are core product quality, not back-office detail.
5. AI content needs candidate-evidence provenance and confirmation gates.
6. Gmail permission is requested earlier than its value moment in supplied screens.
7. Public claims, `autopilot` language and a privacy-policy review posture are not fully reconciled.
8. A public portfolio reference exposed identity-document numbers and requires immediate remediation.
9. Paid acquisition cannot be interpreted until activation, D7 repeat use, attribution and margin are measured.
10. India-first global mobility is a plausible wedge, not a settled ICP or corridor.

- HN-010A: close public sensitive-data exposure.

- HN-026: decide and enforce the human-review boundary.
- HN-027: separate TerraTern and HireNudge purposes and consent.
- HN-028A/B: verify privacy controls and the security baseline.

#### Prove

- HN-002: define and instrument activation and outcome.
- HN-005: replace score-first matching with evidence-led alignment.

- HN-008: block unconfirmed factual additions.

#### Operate

# 3. UI/UX

## Founder dashboard content

### Page title

`Move from a feature menu to one clear job-search journey.`

### Journey comparison

#### Current observed pattern

`Profile setup → dashboard cards → user chooses among modules → scores and generators → disconnected tracker.`

#### Proposed concept

`Import evidence → select one source-verified role → review alignment → improve one truthful packet → set the next action → record the outcome.`

### Current versus proposed

| Current observed pattern | Proposed concept | Validation |
|---|---|---|
| Many equal dashboard modules | One stage-aware next action | Task completion and time to first packet |
| Module-first navigation | Job/application packet as context | Navigation errors and comprehension |
| Score-first matcher | Requirements, evidence, gaps and unknowns | Reviewer agreement and user corrections |
| Gmail as profile completion | Connect only when the user sends | Permission acceptance after value; disconnect success |
| Tracker empty state | Save first target job during activation | First tracker action within 24 hours |
| Credits without clear action value | Preview action cost and remaining balance | Pricing comprehension and surprise reports |
| Limited visible history | Versions, diffs, save state and rollback | Restore rate and wrong-version errors |
| Unclear system states | Loading, stale, error, partial, revoked and deletion states | Critical-error recovery |

### Visual direction

`Light, spacious and editorial. True white or light neutral canvas, charcoal text, one controlled HireNudge accent, semantic labels, subtle borders, restrained shadows, strong Geist typography and limited motion.`

### Design decision

`Approve the job-centered prototype and usability criteria before a full product redesign. Mascot, gradients and motion remain subordinate to comprehension, accessibility and performance.`

### Language comparison

| Current/public pattern | Risk | Recommended direction |
|---|---|---|
| `Trusted by 10,000+ Job Seekers` | Count source and period not supplied | Publish with calculation, period and owner or remove |
| `landing interviews faster` | Causal outcome not substantiated | `organize and improve your job-search workflow` until measured |
| `autopilot` / `bulk` | Conflicts with review posture | `assisted`, `draft, review and send` |
| `match score` | May imply hiring probability | `profile-to-role alignment` plus evidence/gaps |
| `ATS score` | Implies one universal employer system | Name parseability, format, stated requirement and evidence checks |
| `fix your resume` | Frames the candidate as defective | `make your evidence clearer for this role` |
| Gmail to complete profile | Permission pressure | `Connect Gmail when you choose to send a reviewed email` |
| `perfect`, `guaranteed`, `job-winning` | Unverifiable promise | `source-backed`, `role-specific`, `editable`, `reviewed` |

### Brand principles

- specific before clever;
- calm and respectful;
- explain why information is requested;
- separate fact, inference and suggestion;
- never imply access to an employer's private decision;
- use India hiring realities without stereotype;
- label sponsorship evidence and uncertainty.

### Naming decision

`Use Nudge Studio only if it becomes the evidence-backed editing space inside an application packet. A cosmetic rename is low value.`

# 8. Retention

## Founder dashboard content

### Page title

`Bring the user back for the next useful action.`

### Principle

`Lifecycle communication follows product state and user consent. It is not a generic hiring-news broadcast.`

### Lifecycle map

| Moment | Value | CTA | Exit rule | Metric |
|---|---|---|---|---|
| Welcome | Explain one-job activation | Select one role | Stop after activation | 24-hour activation |
| Saved job, no packet | Show freshness and next step | Review alignment | Applied, expired or dismissed | Packet start |
| Evidence gap | Ask for proof, not invented numbers | Add or confirm evidence | Dismissed or submitted | Confirmed evidence rate |
| Weekly job digest | Small set of fresh qualified roles | Review jobs | No qualifying jobs means no send | Save/apply and stale-click rate |
| Application follow-up | User-set reminder and reviewed draft | Review next action | Rejected, withdrawn or opted out | Completion and reply |
| Interview reminder | Round plan and practice checklist | Practice one answer | Interview passed or cancelled | Practice completion |
| Inactivity recovery | Resume exact unfinished step | Continue | Cap attempts and suppress | Reactivation and unsubscribe |
| Upgrade | Explain exact benefit after value | Compare plans | Stop pressure after decline | Paid conversion and refunds |
| Referral | Invite after verified value | Refer | Fraud/frequency limit | Activated referrals |
| Win-back | Update search status; export or pause | Update status | Search closed or opted out | Return without complaint |

### Search-status modes

`Active`, `Interviewing`, `Paused`, `Offer received`, `Search ended`.

Status changes the home, reminders, upgrade prompts and retention interpretation. It is user-confirmed, not inferred from desperation or inactivity.

### Controls

- separate product-critical and marketing messages;
- category preferences;
- global frequency cap;
- quiet or pause mode;
- one-click unsubscribe where required;
- suppression list;
- no sensitive employer, application or immigration details in subject lines or previews.
